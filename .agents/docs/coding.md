# Coding

TypeScript / Vue.js のベストプラクティス、命名規則、アンチパターンについてです。

## TypeScript

- Strict モードが有効化されています。
- 変数や関数の型に `any` を使用することは原則認められません。
- 冗長な型注釈は避け、可能な限り推論に任せます。
- ユニオン型が指定可能な場合は、ユニオン型で状態を明示的に表現します。
- 関数定義は、可能な限りアロー関数（`const func = () => {}`）で記述する必要があります。

## Vue.js

- Vue.js のコンポーネントは「単一ファイルコンポーネント（Single-File Components, SFC と略記）」で実装します。
- `computed` は、リアクティブな依存関係に基づき計算結果がキャッシュされます。アプリケーションの動作を高速化するため、繰り返し実行される複雑な処理については適宜 `computed` を使用して再計算を避けるようにします。
- `app/components/` 内に作成するコンポーネントは、複数単語で構成する必要があります。また、SFC のファイル名は PascalCase にする必要があります。
- 親コンポーネントと密に結合された子コンポーネントには、親コンポーネント名をプレフィックスとして含める必要があります（例：親コンポーネント `BadgeList` と子コンポーネント `BadgeListItem`）。
- コンポーネントのプロパティ定義（Props）は、可能な限り詳細に定義し、少なくとも型情報を指定する必要があります。また、プロパティ定義（Props）は、宣言時については常に camelCase にする必要があります。使用する際は `kebab-case` にします。
- `v-for` を用いてリストレンダリングを行う際には、必ず一意となる `key` を指定します。また、同じ要素に対して `v-if` と `v-for` を同時に指定することは認められません。`v-if` をコンテナ要素に移動するか、`computed` を用いてデータのフィルタリングを行なってからリストレンダリングを行います。
- `v-bind:` ではなく `:`、`v-on:` ではなく `@`、`v-slot:` ではなく `#` のように、省略形がある場合には可能な限り省略形を使用します。
- SFC 内の要素は `<script>`、`<template>`、`<style>` の順に並べる必要があります。

## Imports

以下の順序で `import` 文を記述します。

1. 型情報（`import type` を使用する）
2. 外部ライブラリ
3. 内部モジュール
4. スタイル

優先度が同じものがある場合は、以下の順序で記述します。

1. `@` から始まる（スコープがある）もの（`@/` は内部モジュールのため例外）
2. `a` から `z` までアルファベット順（`a` から始まるものを先に記述する）

## Accessibility

- 適切な HTML タグ（`<button>`、`<main>`、`<header>` など）を使用し、セマンティック HTML を心がけます。
- 必要に応じて `aria-label`、`aria-describedby` など WAI-ARIA 属性を付与します。
- 可能な限り操作をキーボードで実行可能にします。
- `focus-visible` で適切なフォーカススタイルを適用します。

## Comments

- 変数や関数には JSDoc コメントを付与します。
- 不要なコメントは削除し、コメントアウトは残さないようにします。
